### **Название задачи:** ADR-2 Передача ставок в кол-центр
### **Автор:** --
### **Дата:** 26.06.2025

### **Функциональные требования**

|**№**|**Действующие лица или системы**|**Use Case**|**Описание**|
| :-: | :- | :- | :- |
| UC1 | Сотрудник отдела депозитных продуктов (бэк-офис), АБС, системы кол-центров | Обновление ставок по депозитам для кол-центров | 1. Сотрудник отдела депозитных обновляет ставки по депозитам в АБС. <br/> 2. АБС передает информацию об изменениях в систему кол-центра. <br/> 3. Для партнерского кол-центра формируется файл с информацией по ставкам и передается по доступному каналу связи в автоматическом режиме. |
| UC2 | Клиент, сотрудник кол-центра, система кол-центра | Консультирование клиента по актуальным ставкам банка во время звонка | 1. Клиент звонит в банк для получения консультации по ставкам. <br/> 2. Сотрудник кол-центра консультирует клиента в соответствии с переданными в систему кол-центра данными по ставкам. |

### **Нефункциональные требования**

|**№**|**Требование**|
| :-: | :- |
| +R  | **+ Ограничения (Restrictions)** ||
| +R1 | Шифрование трафика при передаче данных ||
| +R2 | Партнерский кол-центр не может сделать API-вызовы ||
| +R3 | Партнерский кол-центр может получать актуальные ставки в виде файлов (например, через SFTP-протокол) ||

### **Решение**

Диаграммы контекста и контейнеров выполнены в draw.io: [C4-Diagrams.drawio](./C4-Diagrams.drawio)

Обновление ставок по депозитам производится сотрудником отдела депозитных продуктов в АБС (предполагается, что доработка АБС в части совместной работы сотрудников по кредитным и по депозитным продуктам произведена на раннем этапе).
Далее информация об обновлениях помещается в очередь сообщений Kafka, на которую подписана система кол-центра.

Для обмена данными с партнерским кол-центром предлагается разработать сервис экспорта, который также по Kafka получает обновления и формирует файл требуемого формата. Далее этот же сервис пересылает по SFTP протоколу данные во внешний (партнерский) кол-центр.

### **Альтернативы**

В качестве альтернативы протоколу SFTP можно рассмотреть отправку файла в партнерский кол-центр по e-mail (можно рассматривать этот канал в качестве резервного, в случае недоступности системы партнерского кол-центра или даже дублировать информацию по нему всегда). Это потребует дополнительных организационных усилий со стороны команды партнерского кол-центра: кто-то должен взять на себя обязанность в переносе информации в систему для дальнейшего удобства сотрудников (ручная операция).

Еще одним решением проблемы передачи данных во внешнюю систему было бы использование S3 хранилища, например, у облачного провайдера.

**Недостатки, ограничения, риски**

Информация в файле со ставками может быть искажена непреднамеренно во время передачи. Нужно озаботиться о защите целостности данных.
